# Правила уведомлений отчёта изменений

Утверждены владельцем 05.10.2026, включая уточнения о полноте снимков
и сохранении исторического знания. Пороги и маршрут не меняются.

## Срочное: три самостоятельных события

Первое появление, окончание льготного срока и переход статуса
«Технический дефолт» → «Дефолт» показываются отдельно.
Идентификатор обязательства — id записи источника, не id выпуска.
Ключ уведомления — (id записи, вид события); каждый ключ выводится
одной строкой в окне своего первого наступления. Повторная сборка того же
отчёта воспроизводит его, но не переносит уведомление в последующие окна.

Первое появление и переход статуса устанавливаются только по успешно
полученным полным датированным снимкам. Проверяются items, total, count,
уникальные непустые id и отсутствие признака ошибки/неполноты. Ошибочный,
неполный или пропущенный снимок не доказывает отсутствие записи.
Первое появление датируется первым полным снимком с записью после полного
снимка без неё. Запись уже в начальном полном снимке не считается новой.
Дата объявления источника называется отдельно, не подменяется датой снимка.

Окончание льготы датируется сроком, известным к его наступлению, если запись
уже была известна. Подтверждённое к этому дню исполнение снимает уведомление;
отсутствие даты исполнения не доказывает новый неплатёж. Переход статуса
датируется первым полным снимком «Дефолт» после полного снимка
«Технический дефолт» той же записи. Это дата наблюдения перехода;
точная дата изменения статуса источником не установлена. Если прежнего
статуса нет, переход не утверждается. Пропуски снимков называют границу знания.

Используются только сведения снимков не позже даты отчёта. При последовательном
восстановлении первоначальная дата уже наступившего события сохраняется.
Позднее исполнение и исправление дат не удаляют и не переносят его задним
числом. Уточнения показываются отдельно по дню наблюдения исправления,
без повторного уведомления того же вида. До наступления события действует
уже известный уточнённый срок. Повторный переход не создаёт второй ключ.

Каждая строка называет вид и дату события, выпуск, id записи, дату и статус
последнего доступного снимка записи не позже даты отчёта. При отсутствии
записи в последнем полном снимке это называется отдельно и не считается
подтверждением исполнения. Пустая actual_date печатается как «дата исполнения
в снимке отсутствует; это не доказательство нового неплатежа».
Датированные файлы снимков сохраняются неизменными; недатированная ручная
доставка не даёт доказательства даты наблюдения. Без полных снимков
события обязательств не установлены, а не проверены с нулём срабатываний.

## Подгруппа и предписанное действие

При прежней корзине смена подгруппы показывается отдельным сообщением,
только если различаются сохранённые action_code прежней и новой точки.
Названия и текст действий не участвуют в сравнении. При неизвестном
прежнем action_code смена действия не утверждается; пробел называется явно.
Коды фиксируют смысл действия; техническое переименование сохраняет код.
Действие сохраняется общим писателем наблюдения и пересчёта в
`routing_history.inputs.action`: code, text, subgroup, subgroup_name.
Сравнение идёт против суточной точки расписания. Смена корзины в этот
раздел не дублируется. Старая история без кода не переписывается.
